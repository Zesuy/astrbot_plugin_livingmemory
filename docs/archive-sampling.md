原文查询中的概览与人物语料
========================

`query_chat_events` 保留原有 `lookup`、`time_read`、`read`，新增 `overview` 和 `style_sample`。仍由外层模型决定调用，不新增自动提示词注入、内部 LLM 总结、事件库或数据库迁移；原有模糊记忆和发送归档继续工作。

`overview` 用于未知话题的时段回顾。按北京时间把给定范围分成八段，每个有消息的时段先分配一个最多五条的连续片段，剩余预算按消息密度分配最多三条的片段。在各段内按消息序号分区取样，避免只读最早一页或只查已知关键词。默认返回不超过四十条；模型可以增加 `page_size`，或按返回的建议时间范围用 `time_read` 补读。建议补读范围为样本前后各五分钟，并非已识别的事件边界。

概览仅在采样视图中折叠同作者、同角色、精确同时间和同正文的旧导入副本。不同原生消息不折叠；未知作者或未知时间不折叠。归档与原有精确读取不变，返回代表消息的原文句柄，并分别报告原记录数、采样视图记录数和折叠副本数。

概览不按作者过滤。指定 `person` 时，额外返回该人的留存发言时间与无发言区间；不指定人物时不附加活动时间线。`person=我`、`person=你` 在工具入口分别绑定当前请求者和机器人账号。无法解析的人物返回歧义，不改成其他人。当前触发消息通过捕获时缓存的 UID 排除；没有缓存时不凭文本猜测 UID。无发言不证明离线或未读，有发言也不证明一直在看群。返回的区间有数量上限与截断标记，不自动选择最长区间。

`style_sample` 要求一个明确人物，默认查询最近三十个日历日。先筛出具有原生 Plain 组件的候选，再跨时段抽取，防止图片与文字交替时只取到图片；同一时段内先覆盖候选两端，再二分取内部样本，避免只取最早一批。短句保留、相同文字去重、同一十分钟最多两条，最多三十二条。命令形态文本被过滤；长文可保留并标注截断。不假定每个以 user 角色入档的账号都是人类。

风格结果的 `text` 是本人提交的 Plain，`quoted_context` 单独保留引用且标注截断。Plain 不能证明原创或稳定人格；没有原生组件边界的旧记录不冒充本人正文。时间质量独立报告。`original_evidence_handle` 可以展开原始完整消息，原文续读偏移不会被投影正文的偏移污染。

示例工具参数：

```json
{"query":"今天我没发言时聊了什么","mode":"overview","person":"我","time_range":"今天"}
```

```json
{"query":"总结最近一周的话题","mode":"overview","time_range":"最近一周","page_size":80}
```

```json
{"query":"模仿雪地卡瓦重的说话方式","mode":"style_sample","person":"2232117857"}
```

时间窗口最多三十一个日历日。“今天”在午夜后仍指当前北京时间日期；“最近一周”包含今天与前六个日历日；“昨晚”沿用昨天十八点至今天六点的约定。实际截止时间不超过查询时点。

交付与局限：默认页的正文预算在样本间分配，返回实际交付的时段和来源 UID；较小页数可能只展示部分采样。`ok` 表示本次选中证据交付成功，不表示话题全部找到。判断是否继续补读应以能否回答问题为准，不要求遍历归档。采样可能漏掉短话题，其他 Bot 的总结也不构成独立事实证据。工具描述提供选用指引，但不会强制模型调用或保证模型正确归因。
